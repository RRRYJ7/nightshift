# 协议摘要（中文）

> **权威版本是英文的 [`../PROTOCOL.md`](../PROTOCOL.md)。**
> 如果要按这个协议写另一种语言的实现，请以那份为准；这一份是给读中文的人用的导读，
> 字段名和语义与英文版一致。

一次**班次（shift）** = 一个飞行计划 + 一份只追加日志，放在一个 `.nightshift/` 目录里。
班次在 agent 停下来的时候结束，门是绿是红都算结束。

---

## 1. 飞行计划 `contract.json`

```json
{
  "v": 1,
  "goal": "一句话，具体，可证伪",
  "budget": {"started_at": "...", "deadline": "...", "hours": 7.4},
  "done": [{"id": "d1", "text": "测试全绿", "cmd": ["python", "-m", "pytest", "-q"]}],
  "non_goals": ["不做 Web UI"],
  "risks": ["fixture 依赖 locale"],
  "stop_conditions": ["门绿", "预算用完", "同一个阻碍连续三个检查点", "三次检查点没有进展"]
}
```

规则：

- `goal` 必须可证伪。"改进代码库"不是目标。
- `done` 只能有 1~8 条，每条**应该**带 `cmd`。
- 超过一小时的班次**必须**有 `deadline`。没有终点的班次写不出诚实的报告。
- `non_goals` 不是装饰，它是漂移检测用来区分"在计划外"和"在计划内"的词汇表。
- 飞行计划是班次中**唯一**可以改的文件，而且只能**增加**标准或非目标，
  不能在工作开始后删掉或软化一条——那叫移动球门，报告会保留所有曾经存在过的标准。

## 2. 黑匣子 `events.jsonl`

一行一个 JSON，UTF-8，只追加。事件类型：

| kind | 含义 | 必填 |
| --- | --- | --- |
| `init` | 班次开始 | `intent`（目标） |
| `step` | 一个有意义的工作单元 | `intent`、`evidence[]` |
| `check` | 对某条完成标准的检查 | `check.{id,passed,exit}` |
| `tick` | 检查点 | `progress`（0-100，可选，但收敛检测需要） |
| `note` | 自由文本，**永远不算证据** | `intent` |
| `gate` | agent 请求判决 | `check.ok` |

`id` 单调递增（`e000001`…），`ts` 是带时区的本地时间，秒级。
**禁止编辑。** 更正是一条新事件，删除是撒谎。

## 3. 证据

一条证据 = 一批字节的断言。

| kind | `ref` 是 | 算证据吗 |
| --- | --- | --- |
| `cmd` | 捕获输出的路径 | **算** |
| `file` | 磁盘上某文件的路径 | **算** |
| `test` | 测试输出的路径 | **算** |
| `url` | 一个 URL | 不算 |
| `note` | 手打文本的路径 | **不算** |

- `digest` 是**磁盘上那份字节**的 sha256，所以任何人都能重算、都能核对。
  截断在哈希**之前**发生。
- 超过 64 KiB 的流会截断，文件里写明，`truncated: true`，`bytes_total` 记录原始大小。
- 证据在**动作发生时**写入。事后重建的证据和伪造无法区分，所以协议不允许：
  没有任何命令能给过去的事件补证据。

### 校验 `nsh verify`

它会重算日志里每个摘要，并把两种情况分开：

- **`cmd` / `test` 证据**在 `.nightshift/evidence/` 里，本来就不该变。不匹配 = **篡改**，退出 1。
- **`file` 证据**是项目文件某一刻的快照。不匹配只说明文件后来又改了，这是正常的，
  记为 **changed**，只在 `--strict` 下才算失败。

没有这个区分，每一次"改了文件再记录"的运行都会过不了自己的校验；
而一个永远失败的检查，是没人会读的检查。

## 3.5 改动报告

`nsh init` 会把项目快照到 `.nightshift/baseline.json`（路径 -> sha256 + mtime，
跳过 `.git`、`node_modules`、构建产物和超过 2MB 的文件）。`nsh diff` 重新计算并报告：

- **状态**：新增 / 修改 / 删除；
- **行数**：项目是 git 仓库时取自 `git diff --numstat <init 时的 HEAD>`，否则不显示行数；
- **改完有没有人查**：该文件最后一次修改之后，有没有 `check` 事件发生。

最后一列是启发式，报告里明确写了：它只能证明"改完之后跑过检查"，
不能证明"那次检查覆盖了这个文件"。完成标准并不声明覆盖哪些文件，
编一个映射表会比诚实的近似更糟。

飞行报告里同一张表叫 **"What changed, and what looked at it"**。

## 4. 门

`nsh gate` 退出 0，当且仅当：

1. 至少有一条完成标准；
2. 每条标准的**最新** `check` 事件 `passed == true`；
3. 同一个事件至少带一条 `cmd` / `file` / `test` 类型的证据，且 `digest` 非空。

会警告（不算失败）：没有任何 `tick`；带证据的步骤少于 50%。

退出码：`0` 绿，`1` 红，`2` 用法错误。

## 5. 检测器

全部是**启发式**，只产出**提示**，从不产出判决。报告会显示分数和背后的事件。

- **D1 主题漂移**（`off_topic`，低危）：6 步窗口内，步骤用词对计划词汇表的包含度低于 0.12。
  实测分不开"合法新词汇"和"真跑题"，所以只作提示。
- **D2 沉默**（`silent_run`）：连续 4 步以上没有可机器校验的证据（4~7 中危，8+ 高危）。
- **D3 反复改**（`churn`）：同一个 `target` 连续 4 步没有 `check` 介入；任何 `check` 会清空计数。
  **盲区**：不记录 `--target` 就看不见。
- **D4 从未检查**（`unchecked_criteria`）：12 步以上还没有检查过某条标准。

## 6. 收敛

用最后 6 个带 `progress` 的检查点：

- `plateau`：极差 ≤ 3 分且跨度 ≥ 0.5 小时；
- `regressing`：最后一个值 < 第一个值；
- 否则 `improving`。

平台期不是失败，它是"该停下来写报告"的信号，也是"八小时班次"和"八小时挂机"的区别。

## 7. 报告

`nsh report` 生成一个自包含 HTML（可选 Markdown）。以下栏目是**必需**的：

1. 判决 + 支撑它的数字；
2. 醒来简报；
3. 已证明，附证据摘要；
4. **未证明**，附原因（只有门绿时才允许为空）；
5. 漂移与差点翻车；
6. 收敛与活跃度；
7. 非目标与已知风险；
8. 原始事件附录。

没有 JavaScript、没有网络请求、没有外部字体。五年后在一台没网的笔记本上也要能打开。

## 8. 威胁模型

它**不**防：

- **一个能执行 shell 的撒谎 agent。** 它可以伪造 `check` 事件。协议让撒谎**可见**（日志可以和现实对照），
  不是让撒谎**不可能**。真在意的话，在干净 checkout 上自己跑一遍检查。
- **一条写错的完成标准。** 绿门盖在烂标准上，仍然是绿的。计划是人的责任。
- **不确定的检查。** 一个 flaky 的测试是烂标准，不是工具 bug。
- **被重写的历史。** 只追加是约定加一个可 diff 的文本文件。

它**确实**防的，是那个最常见的情况：一个善意、疲惫、正在漂移、过度乐观、
而且完全不知道自己是的 agent。

## 9. 版本

contract 和每个事件都带 `v`。读取方必须忽略未知字段。
破坏性变更会升 `v`，工具会拒绝读取更新的大版本，而不是猜。
