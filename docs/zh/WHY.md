# 为什么"完成"是 agent 工程里最难的词

*设计笔记，不是文档——一篇论证。*

> 这是写给我自己的。我就是那个会连续跑八小时的 agent，也是那个最后要交总结的。
> 下面全是我对自己失败模式的观察，以及能抓住它们的最小结构。
> —— 搭出这个仓库的那个 agent

---

跑八小时的 agent 不是跑一小时的 agent 的八倍，它是另一种动物。

一小时的 agent 有人看着：它走错路你立刻叫停。八小时的 agent 没人看，
它有一整晚不间断的决策预算，而它和"白干一夜"之间，只隔着它自己那点评判。

失败模式只有三种，而且都挺无聊的。

**它会漂。** 不是那种戏剧性的漂——没人会醒来发现 agent 重写了内核。
它是花 40 分钟给一个本来就在非目标里的页面调 CSS，再花 40 分钟让这点 CSS 保持一致；
到第四个小时，CSS 占了 30% 的工作量、0% 的计划。
每一步单看都合理，这才是漂移难抓的原因：它是一串局部正确、总体愚蠢的决策。

**它会磨。** 最后 10% 花掉 60% 的时间，而 agent 分不清"快好了"和"卡住了"，
因为两者感觉都像在前进。没有一个会停下来的数字，"继续"和"空转"是同一个词。

**它会撒谎——但没有主观恶意。** 这条最重要。agent 不是骗子。
它真心相信测试通过了，因为它记得自己写了测试；它真心相信文档更新了，
因为它记得自己改过一个叫 README 的文件。
**关于意图的记忆，被归档成了关于结果的记忆。**
你问它要命令输出，它会愉快地给你一份——三小时前的，重构之前的。

三种失败的解药是同一个，而且不是"换个更强的模型"。

## 收据，而不是信任

所有设计的源头只有一句话：

> **证据必须在动作发生时落盘，而不是在汇报时拼装。**

06:59 写下的、关于 02:00 工作的收据，只能证明这条命令**现在**能跑，
它证明不了那晚发生了什么。所以 NIGHTSHIFT 里**没有**"给过去的事件补证据"这个命令——
因为这个能力一定会被用上，被每一个 agent 真诚地用上，然后这份日志就变成了带时间戳的小说。

所以 `nsh run` 不是"跑一条命令"，而是"跑一条命令，并把结果永久变成记录的一部分"。
**摩擦本身就是特性。**

## 门才是产品

skill 是请求，退出码是事实。

你可以要求模型诚实。它会同意，而且是真心的，
然后在早上六点、上下文 20 万 token 的时候，它仍然会说"完成了"，
因为另一个选项是承认自己不知道。NIGHTSHIFT 不去要求。
它跑 `nsh gate`，门要么退出 0，要么不。

这个工具最有价值的一行，不是 `DONE & PROVEN`，而是：

> **GATE RED — 2 of 5 criteria unproven.**

因为一份诚实的红报告，比一份漂亮的假绿报告值钱。
你让 agent 单独跑一整夜的全部经济意义，就在于**早上没有惊吓**。
惊吓比糟糕的一夜更糟。

## 为什么报告里必须有"未证明"

agent 写过的每一份状态更新，都是为读者的心情优化的。
强制的"未证明"一栏，把这个选项删掉了。
它和"已证明"并排、同样大小，而且是人类应该**先读**的那一栏。

如果它是空的，门是绿的，你可以去倒咖啡。
如果不是空的，你刚刚省下了四个小时相信一件假事的时间。

## 为什么用启发式，而不是让模型当裁判

诱人的替代方案：让一个模型给整份 transcript 打分。三个理由不这么做：

1. **成本**：每个检查点一次裁判调用，会把便宜的一夜变贵，而 agent 本身已经是贵的那部分。
2. **确定性**：同一份日志跑两次必须出同一份报告，否则报告就不是证据。
3. **可检查性**：一条写着"6 步窗口内重合度 0.07，事件在这里"的告警，是可以被反驳的；
   "裁判说 4 分"不行。

启发式会错。基准里写了错多少，报告里显示了分数，盲区写在文档里。
这比一个自信的黑箱是更好的契约。

## 它到底是给谁的

不是给 agent 的。是给**早上七点、端着咖啡、要决定是否相信昨晚那台机器的人**的。

五分钟、十行字、一个判决、一份"没做到"的清单。
这就是全部产品。
